# OpenJobs delivery controls

Apply these controls to multi-agent coding work in this repository.

## Board and roles

- Use the persistent OpenJobs board: `hermes kanban --board openjobs ...`.
- `openjobsorchestrator` decomposes, gates, and integrates; it does not implement feature code.
- `openjobsworker` receives one bounded implementation task at a time.
- A coding task with more than one independent lane must be represented as Kanban cards. Use parent links for actual dependencies: implementation → review → integration.

## Worktree and branch discipline

- Every writer gets an isolated worktree and an explicit base commit SHA in its task body.
- Never launch two writers in the same worktree.
- Before independent review, testing, or cherry-picking, freeze the writer: confirm its managed process and OS child processes have exited, then record `git status`, `git diff --stat`, and HEAD.
- If a worker is detached after an interrupted wait, inspect process state and the worktree before relaunching anything. An interrupted wait is not proof that the worker stopped.
- Rebase or cherry-pick onto the current canonical integration branch before canonical verification. A stale worktree must not be treated as a final result.

## Validation budget

- Worker worktrees run focused tests, producer/consumer typechecks, touched-file lint, and a client build only when UI changes.
- Reviewers are read-only and return concrete exploit/failure mode, invariant, and minimal fix for every BLOCKER/HIGH/MEDIUM finding.
- Allow at most one writer → one reviewer → one fixer → one re-review loop. Escalate or simplify the design instead of starting unbounded review loops.
- Only the canonical integration lane runs full CI parity. Run one full CI per completed wave; never run multiple full suites concurrently.

## Status and communication

- Report status only from the canonical SHA and stable process state: running, detached, failed, blocked, or complete.
- Mark output from superseded commits/worktrees as historical; do not treat it as a current blocker.
- Include the active canonical SHA, current gate, exact test result, and remaining risk in progress updates.
